1. Lexical Analysis (lexer.java)

Converts source character stream into language tokens.

Input: String source Output: List<Token>

The Lexer (Scanner) reads the source text character by character. It strips whitespace and newlines, identifies keywords (let, print, if, else, while, end), integer numbers, identifiers (Var), and operators (+, -, *, =). Each token records its exact line and column.

Function Input Output Description
current() None char Returns the character at pos, or '\0' if EOF is reached.
peek() None char Looks at pos + 1 without advancing the scanner position.
advance() None void Moves forward one character, updating line and column tracking.
add(type, text, atLine, atCol) TokenType, String, int, int void Constructs a new Token instance and appends it to tokens.
error(message, atLine, atCol) String, int, int void (throws) Throws a RuntimeException detailing the illegal character and line/column.
scan() None List<Token> The main loop scanning all tokens, appending EOF, and returning the token list.

2. Syntax Analysis (parser.java)

Constructs the Abstract Syntax Tree (AST) using recursive descent.

Input: List<Token> Output: List<Stmt> (AST)

The Parser transforms the linear token stream into a hierarchical Abstract Syntax Tree. It enforces precedence: * and / (Terms) bind tighter than + and - (Expressions), and supports structured statements with block nesting.

Function Input Output Description
parseProgram() None List<Stmt> Top-level entry point; loops through statements until EOF.
parseStatement() None Stmt Dispatches parsing of let, print, if, while, or Var = expr.
parseBlock(stopAtElse) boolean List<Stmt> Parses block statements inside if/while until end or else.
parseCondition() None Expr Parses conditions of the form left = right.
parseExpression() None Expr Parses left-associative addition and subtraction: term (+/- term)*.
parseTerm() None Expr Parses left-associative multiplication and division: factor (*// factor)*.
parseFactor() None Expr Consumes primary values: either numeric literals or variable names.

3. Semantic Analysis (SemanticAnalyzer.java)

Enforces scope rules and variable declaration constraints.

Input: List<Stmt> (AST) Output: Valid / Exception

The Semantic Analyzer ensures that: 1. Every variable is declared with let before it is used in any expression or assignment. 2. Variables cannot be declared more than once (duplicate declarations are rejected).

Function Input Output Description
analyze(program) List<Stmt> void Clears the declared symbol set, then verifies the program sequentially.
checkStatements(statements) List<Stmt> void Traverses statements, verifying declarations on LET, assignments, print calls, and loop/if bodies.
checkExpr(expr) Expr void Recurses into binary expressions; asserts all NAME variables exist in declared.

4. Code Generation (CodeGenerator.java)

Emits runnable target Java code from the validated AST.

Input: List<Stmt> (AST) Output: String (Java Code)

The Code Generator translates MiniLang AST nodes into Java source code, generating appropriate variable typing (int), statements, indentation, and wrapping them in class GeneratedProgram { public static void main(String[] args) { ... } }.

Function Input Output Description
indent(depth) int depth String Returns 4 spaces per nesting depth level for readable indentation.
expression(expr) Expr String Converts an expression AST to Java string, parenthesizing binary operations.
statements(list, out, depth) List<Stmt>, StringBuilder, int void Emits Java code for statements with proper indentation and block braces.
generate(program) List<Stmt> String Wraps emitted statements in a class and main method; returns final Java source code.

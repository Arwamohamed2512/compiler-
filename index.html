1. Lexical Analysis (Scanner / Tokenizer)

File: lexer.java
Input: String source (Character Stream) Output: List<Token> (Token Stream)

The Lexer is the compiler's initial translation phase. It scans through raw source text character-by-character, discards insignificant whitespace and carriage returns, preserves essential line breaks as NEWLINE tokens, and groups characters into typed tokens (identifiers, numbers, keywords, and operators) while recording exact source coordinates for error diagnostics.

Function Input & Output Responsibility & Implementation Details
current() Input: None
Output: char		 Returns the character at index pos, or '\0' if the end of source string has been reached.
peek() Input: None
Output: char		 Looks ahead at character pos + 1 without advancing the scanner pointer.
advance() Input: None
Output: void		 Consumes one character. On \n, increments line and resets column = 1; otherwise increments column.
add(type, text, atLine, atCol) Input: TokenType, String, int, int
Output: void		 Creates a new immutable Token instance with source coordinates and appends it to the internal tokens list.
error(message, atLine, atCol) Input: String, int, int
Output: throws RuntimeException		 Aborts lexical scanning, throwing a detailed diagnostic error indicating the offending character and its line/column numbers.
scan() Input: None
Output: List<Token>		 Main lexical loop. Iterates character-by-character, delegates keyword vs identifier detection, adds symbols, appends final EOF, and returns tokens.

2. Syntax Analysis (Recursive Descent Parser)

File: parser.java
Input: List<Token> (Tokens) Output: List<Stmt> (Abstract Syntax Tree)

The Parser translates the flat sequence of tokens into a hierarchical Abstract Syntax Tree (AST). It enforces language grammar rules and mathematical precedence: terms involving multiplication (*) and division (/) bind tighter than expressions involving addition (+) and subtraction (-).

🌳 Visualizing Expression Precedence in the AST

How the parser guarantees multiplication binds tighter than addition in let x = 1 + 2 * 3:

[Stmt.LET] name = "x"
└── expr: [Expr.BINARY] op = "+"
├── left: [Expr.NUMBER] value = "1"
└── right: [Expr.BINARY] op = "*" (Evaluated First)
├── left: [Expr.NUMBER] value = "2"
└── right: [Expr.NUMBER] value = "3"

🏷 Input Tokens

let score = age + 10

🗂 Parsed AST Structure

Stmt.LET(
  name: "score",
  expr: Expr.BINARY(
    op: "+",
    left: Expr.NAME("age"),
    right: Expr.NUMBER("10")
  )
)
Function Input & Output Responsibility & Implementation Details
parseProgram() Input: None
Output: List<Stmt>		 Top-level entry point. Repeatedly skips newlines and parses top-level statements until reaching the EOF token.
parseStatement() Input: None
Output: Stmt		 Inspects current token: branches to let, print, if, while, or variable assignment.
parseBlock(stopAtElse) Input: boolean
Output: List<Stmt>		 Parses a sequence of statements inside block bodies until reaching end, else (if stopAtElse is true), or EOF.
parseCondition() Input: None
Output: Expr		 Parses conditional expressions: parses left expression, checks for =, and parses right expression.
parseExpression() Input: None
Output: Expr		 Parses addition (+) and subtraction (-) using a left-associative while loop.
parseTerm() Input: None
Output: Expr		 Parses multiplication (*) and division (/), binding tighter than addition and subtraction.
parseFactor() Input: None
Output: Expr		 Consumes atomic leaf tokens: either a numeric constant (Number) or a variable name (Var).
consume(type, message) Input: TokenType, String
Output: Token		 Asserts current token matches type and advances; throws a syntax error if there is a mismatch.

3. Semantic Analysis (Symbol Table & Scope Verification)

File: SemanticAnalyzer.java
Input: List<Stmt> (AST) Output: Valid / RuntimeException

The Semantic Analyzer validates context-sensitive rules that grammar cannot enforce. It maintains a Symbol Table (a Set<String> declared) to guarantee:
1. Use-Before-Declaration: Variables cannot appear in expressions or assignments without being declared via let first.
2. No Duplicate Declarations: Variables cannot be declared more than once in the same program scope.

📝 Visualizing Symbol Table State Progression
Initial State
declared: { }
→
After: let age = 20
declared: { "age" }
→
After: let score = age + 10
declared: { "age", "score" }
→
On: print total
Throws: 'total' not declared!

✔ Valid Program Execution

let a = 10
let b = a + 5
print b
// Status: PASSED ✔
// Symbol Table: ["a", "b"]

✘ Rejected Semantic Violations

// 1. Undeclared Variable Usage:
print total
// Throws: "Semantic error: variable 'total' is not declared"

// 2. Duplicate Declaration:
let a = 10
let a = 20
// Throws: "Semantic error: variable 'a' is declared twice"
Function Input & Output Responsibility & Implementation Details
analyze(program) Input: List<Stmt>
Output: void		 Clears the internal declared set and initiates top-to-bottom checking of all program statements.
checkStatements(statements) Input: List<Stmt>
Output: void		 Validates statements in source order:
  • LET: Checks initializing expression first, asserts name is not already in declared, then records the variable.
  • ASSIGN: Verifies target name is already in declared, then checks expression.
  • PRINT: Validates expression variables.
  • IF / WHILE: Checks condition and recursively checks nested body blocks.
checkExpr(expr) Input: Expr
Output: void		 Recursively confirms all variable names (NAME nodes) exist in declared; recurses into BINARY left and right branches.

4. Code Generation (Target Java Synthesis)

File: CodeGenerator.java
Input: Validated List<Stmt> (AST) Output: String (Java Source Code)

The Code Generator is the synthesis backend of the compiler. It walks through the validated Abstract Syntax Tree and translates MiniLang statements into complete, structured Java code, wrapping the statements inside class GeneratedProgram { public static void main(String[] args) { ... } } with accurate 4-space block indentation.

⚡ Visualizing Translation from MiniLang to Java

📄 MiniLang Program

end

☕ Generated Java Code

class GeneratedProgram {
    public static void main(String[] args) {
        int age = 20;
        int score = (age + 10);
        System.out.println(score);
        if ((score = 30)) {
            System.out.println(1);
        }
    }
}
Function Input & Output Responsibility & Implementation Details
indent(depth) Input: int depth
Output: String		 Generates a string with depth * 4 spaces for clean, readable Java code indentation.
expression(expr) Input: Expr
Output: String		 Converts an expression node to Java text, enclosing binary operations in parentheses (left op right) to preserve evaluation grouping.
statements(list, out, depth) Input: List<Stmt>, StringBuilder, int
Output: void		 Recursively translates AST statements into Java statements (int name = expr;, if (...) { ... }, while (...) { ... }).
generate(program) Input: List<Stmt>
Output: String		 Wraps emitted statements in class GeneratedProgram { public static void main(String[] args) { ... } } and returns final Java source code.

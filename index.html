Stage 1: Lexical Analysis (Scanner / Tokenizer)

Implemented in: lexer.java
Input: String source Output: List<Token>

The Lexer is the compiler's front door. It reads the source code character by character, tracks line and column numbers, strips non-semantic whitespace and carriage returns, and converts groups of characters into discrete, categorized Token objects.

Function Input Output What It Does
current() None char Returns the character at the current index (pos) or '\0' at EOF.
peek() None char Looks ahead at index pos + 1 without consuming the character.
advance() None void Consumes the current character. Increments line on '\n' and updates column.
add(type, text, atLine, atCol) TokenType, String, int, int void Creates a new Token instance with source location and appends it to tokens.
error(msg, atLine, atCol) String, int, int void (throws) Throws a descriptive RuntimeException pinpointing the exact line and column of an illegal character.
scan() None List<Token> The main loop scanning all tokens in the source until reaching '\0', appends EOF, and returns the list.

Stage 2: Syntax Analysis (Recursive Descent Parser)

Implemented in: parser.java
Input: List<Token> Output: List<Stmt> (AST)

The Parser enforces the grammar of the programming language. It transforms the flat stream of tokens into a hierarchical Abstract Syntax Tree (AST). It encodes mathematical precedence (multiplication and division bind tighter than addition and subtraction) and models compound structures like conditional blocks and while loops.

🌳 Visualizing Abstract Syntax Tree (AST) Hierarchy

For the statement let score = age + 10 * 2, the tree guarantees 10 * 2 is evaluated before +:

[Stmt.LET] name = "score"
└── expr: [Expr.BINARY] op = "+"
├── left: [Expr.NAME] value = "age"
└── right: [Expr.BINARY] op = "*" (higher precedence)
├── left: [Expr.NUMBER] value = "10"
└── right: [Expr.NUMBER] value = "2"

Example Tokens Input

let score = age + 10

Parsed AST Node

Stmt.LET(
  name: "score",
  expr: Expr.BINARY(
    op: "+",
    left: Expr.NAME("age"),
    right: Expr.NUMBER("10")
  )
)
Function Input Output What It Does
parseProgram() None List<Stmt> Top-level routine. Skips newlines and parses statements until reaching the EOF token.
parseStatement() None Stmt Dispatches parsing based on current token: LET, PRINT, IF, WHILE, or ASSIGN.
parseBlock(stopAtElse) boolean List<Stmt> Parses a sequence of statements inside block bodies until reaching end, else, or EOF.
parseCondition() None Expr Parses conditional expressions: parses left expression, matches optional =, and parses right expression.
parseExpression() None Expr Handles addition (+) and subtraction (-) with left-associative tree construction.
parseTerm() None Expr Handles multiplication (*) and division (/), binding tighter than addition.
parseFactor() None Expr Parses primary atoms: integer literal (NUMBER) or variable identifier (NAME).
consume(type, msg) TokenType, String Token Verifies that the current token matches type and consumes it; otherwise throws a parse error.

Stage 3: Semantic Analysis

Implemented in: SemanticAnalyzer.java
Input: List<Stmt> (AST) Output: Valid / Semantic Error

The Semantic Analyzer validates constraints that cannot be checked by syntax grammar alone. It maintains a Symbol Table (a set of declared names) to enforce two core rules:
1. Use-Before-Declaration: Every variable used in expressions or assignments must be declared with let first.
2. No Duplicate Declarations: Declaring the same variable name more than once is an error.

📝 Visualizing Symbol Table State Evolution

→

→
Step 3: print total
Error: 'total' not declared!

Valid Program

let a = 10
let b = a + 5
print b
// Result: PASSED ✔

Invalid Program (Semantic Error)

print total
// Result: FAILED ✘
// RuntimeException:
// "Semantic error: variable 'total' is not declared"
Function Input Output What It Does
analyze(program) List<Stmt> void Clears the declared set and initiates sequential checking of the full program.
checkStatements(statements) List<Stmt> void Traverses each statement in order:
  • LET: Checks initializing expression, rejects if already in declared, then adds name to declared.
  • ASSIGN: Confirms name is in declared, then checks expression.
  • PRINT: Validates expression.
  • IF / WHILE: Checks condition and recursively checks nested statement bodies.
checkExpr(expr) Expr void Recursively verifies that every NAME identifier node exists in declared; recurses on BINARY left and right operands.

Stage 4: Code Generation

Implemented in: CodeGenerator.java
Input: Validated AST Output: Complete Java Source Code

The Code Generator is the synthesis backend of the compiler. It walks through the validated Abstract Syntax Tree and emits target code. In this project, it compiles MiniLang into complete, idiomatic Java code, wrapping the statements inside class GeneratedProgram { public static void main(String[] args) { ... } } with accurate 4-space block indentation.

Source MiniLang Program

Generated Java Program

class GeneratedProgram {
    public static void main(String[] args) {
        int age = 20;
        int score = (age + 10);
        System.out.println(score);
    }
}
Function Input Output What It Does
indent(depth) int depth String Returns a string containing depth * 4 spaces to format blocks with standard indentation.
expression(expr) Expr String Translates expression nodes to Java syntax. Encloses binary operations in parentheses (left op right) to preserve grouping.
statements(list, out, depth) List<Stmt>, StringBuilder, int void Recursively emits Java statements with appropriate indentation, braces { ... }, and semicolons.
generate(program) List<Stmt> String Creates the outer class GeneratedProgram wrapper and main method, invokes statements at depth 2, and returns the Java source string.
